- MemoryOptimizer budget unit is characters (`_total` uses `_msg_len` semantics: string → `len(content)`, structured content → JSON length, non-serializable → `len(str(content))`); windows: chatgpt/deepseek 128000, gemini 1000000, default 32000, reserve 512.
- `test_bridge.py` needs port 17614 free — run it while the bridge is stopped; every other suite needs the bridge up.
- Bridge launch on Windows: use a background shell job. `Start-Process` inside a short-lived shell call died silently (child killed with the parent); the shell tool's background mode survives.
- Bridge logs go to `logs/bridge_debug.log` (`bridge.py:91 LOG_PATH`, `bridge.py:122 logging.basicConfig(filename=...)`), not to stdout — only warnings/tracebacks reach stderr, which is why the deprecation warning was the only line on the process stream.
- A background shell can lose its handle (`Shell.NotFoundError`) and take the bridge process down without running its shutdown handler (no `bridge stopped` record, no traceback, no ERROR/CRITICAL in `logs/bridge_debug.log`). Diagnosed as tool-side process-tree cleanup, not a bridge regression; the relaunched instance passed the same three live suites and stayed healthy. Redirect the bridge streams to repo files (`> bridge_live.out 2> bridge_live.log`, both gitignored via `*.out` / `*.log`) so a future crash keeps its traceback.
